# 展示站的导航和组件说明（学 Gestalt）

> 2026-11-02，方案。维护者看了 Pinterest 的设计系统 [Gestalt](https://gestalt.pinterest.systems/v1/home)（Apache-2.0），觉得它导航的栏目和组件页的说明做得好，要学过来。
> 只学结构和写法，不搬它的代码和文字。开工前读这份和 `DESIGN-PRINCIPLES.md`；每批做完在第 5 节打勾写日期。决定号从 G1 起（D161 是同一天 TOUCH-REVIEW-PLAN 的外观色块格子）。

---

## 0. 结论

Gestalt 好在两件事，我们都缺：

1. **栏目分开。** 顶栏有 4 个栏目（开始、基础、组件、团队支持），左栏只列当前栏目里的页。
   我们的左栏一次列出 16 组、166 项：开始、基础、10 组组件、模式、模板、小程序、工具全在一列里。想找「颜色」要先翻过 73 个组件。
2. **组件页回答的是「该不该用、怎么用对」，不只是「长什么样」。** Gestalt 每个组件页的顺序是固定的：
   - 一句话说明、也叫什么、状态；
   - 什么时候用 / 什么时候别用；
   - 对错对照（左边对、右边错，各配一个真组件、一句话）；
   - 无障碍、多语言、变体；
   - 文案怎么写；
   - 相关组件，每个后面写一句「什么情况用它」。

   另外还有组件总览页（按字母 / 按分类切换，每个一张卡）和组件状态表（每个组件在设计稿、文档、响应式上做到哪一步）。

我们的组件页已经有演示、状态矩阵、规格、属性、无障碍、规则，比 Gestalt 多「两种实现对照」「小程序」。缺的是：

- 「什么时候用」只有 27 / 73 个组件写了；
- 一个对错对照都没有（`DoDont` 组件只用在设计原则页）；
- 相关组件只是一排名字，不说为什么选它；
- 没有组件总览页，`/components` 是 404；
- 右边的目录不跟着滚动高亮；
- 不说「别的库叫它什么」，也看不出这个组件有没有 React 版、小程序版。

## 1. Gestalt 的做法（2026-11-02 看的 v1 文档）

| 地方 | 它怎么做 |
| --- | --- |
| 顶栏 | 标志 · 开始 · 基础 · 组件 · 团队支持 · 主题开关 · 搜索。当前栏目下面一条线 |
| 左栏 | 只列当前栏目。组件栏目：总览、组件状态、工具类（可折叠），然后 90 多个组件按字母排 |
| 组件总览 | 一句话介绍 +「不知道用哪个？来问我们」；「按字母 / 按分类」两个视图；每个组件一张卡：示意图、名字、一句话 |
| 组件状态 | 一张表：设计稿、文档、响应式、自适应，每格「就绪 / 部分就绪 / 计划中 / 废弃 / 没有」，上面有图例 |
| 组件页头 | 名字、一句话、也叫（Action, CTA）、状态记号、源码 / 最近改动的链接 |
| 组件页正文 | 属性 → 什么时候用 / 别用 → 对错对照 → 无障碍 → 多语言 → 变体（每种一个演示）→ 文案 → 质量清单 → 相关（每个一句话） |
| 演示 | 每个演示下面一排小按钮：暗色、从右往左、改属性、复制代码、全屏 |
| 右边目录 | 两级，滚到哪一节高亮哪一项 |

## 2. 决定

| 编号 | 决定 | 为什么 |
| --- | --- | --- |
| G1 | 顶栏加 6 个栏目：**开始 · 基础 · 组件 · 模式 · 小程序 · 工具**。左栏只列当前栏目的页。模板放在「模式」栏目的第二组；更新记录放在「工具」 | 166 项一列找不到东西。6 个以内一眼能扫完；模板和模式都是「拼好的一整块」，放一起 |
| G2 | 当前栏目由地址决定：`/components`、`/foundations`、`/patterns` 和 `/templates`、`/miniprogram`、`/tools` 和 `/changelog`，其余算「开始」。栏目链接到该栏目的第一页 | 不用每页手写，加新页不会忘 |
| G3 | 顶栏只有一种排法：**品牌 · 栏目 ……… 搜索 · 亮暗 · 外观 · 语言 · GitHub**。栏目紧跟品牌（宽屏时从正文那条线开始），当前栏目用 `aria-current="true"`（它指向栏目的第一页，不一定是这一页，所以不用 `page`）和下面一条 2px 的 `--action` 线（和左栏「当前页」同一种记号，D74：≥ 3:1），不加粗。主题只留一个「切换亮暗」图标按钮；「跟随系统」、圆角、主色、密度、质感全在「外观」弹层里（调节图标），任何宽度都一样。窄了只有两处变化：≤ 1180 搜索框缩成放大镜（和旁边的图标按钮一样没有框），≤ 1023 栏目搬到侧栏最上面两排（手机上就是抽屉最上面）；≤ 480 GitHub 进外观弹层 | 第一版把主题三个按钮、圆角两个按钮也摆在顶栏，窄了再一样一样往弹层里收，维护者看了觉得「乱糟糟的，收纳怪怪的」（2026-11-02）。改成一种排法后，什么东西在哪不随宽度变 |
| G4 | 搜索照旧搜全站（⌘K 不分栏目） | 栏目是给浏览用的，搜索是给知道名字的人用的 |
| G5 | 新增组件总览页 `/components`（和 `/en/components`），三个视图：**按分类**（缺省）· **按字母** · **状态表**。卡片是名字、中英名、一句话，不放示意图 | 示意图要给 73 个组件各画一张，首页的组件墙已经是活的示意。卡片上的一句话就是 registry 的 `summary` |
| G6 | 状态表的列：**网页（HTML + CSS）· React · 小程序 · 两种实现对照 · 说明**。每格只有三种：有 / 部分 / 没有，上面写图例。「说明」看这页写没写「什么时候用 / 别用」「无障碍」「规则」「对错」，四样齐了才算「有」 | Gestalt 的状态表最有用的是让人一眼看出哪里还没做完。「说明」那一列也是给我们自己的待办 |
| G7 | 组件页头加一行：**也叫**（别的库里的叫法，取自 `SEARCH_ALIASES`）和**有哪些实现**（网页 / React / 小程序，有的才写）；再加两个链接：**样式源码**、**改动记录**（GitHub 上那个 CSS 文件和它的提交记录） | 从 Ant Design / shadcn 来的人先找 Modal，看到「也叫」就知道是同一个东西 |
| G8 | 右边的目录跟着滚动高亮当前一节，用 xxd.js 自己的 `spyToc`（`.xxd-toc[data-spy]` 那一套），不另写 | 我们的组件已经会，展示站自己反而没用 |
| G9 | 组件页正文顺序改成：**演示 → 什么时候用 / 别用 → 对错 → 变体（原来的「更多示例」）→ 状态 → 规格 → 属性 → React 属性 → JS → 无障碍 → 文案 → 规则 → 相关**。没写的那节不出现 | 先看到东西，再判断该不该用、怎么用对，最后才是查属性。演示放第一，因为我们的演示就是读者最想看的 |
| G10 | registry 加三个可选字段：`dos`（对错对照，`[{ do, dont, doMarkup?, dontMarkup? }]`）、`writing`（文案要点）、`related`（`[{ name, why }]`）。英文写在 `registry.en.js` 对应位置。没写 `related` 时照旧列同类组件 | 都是说明文字，和 `use` / `avoid` 放在一起，同一份数据中英两版、`/md/` 和 `llms.txt` 也能读到 |
| G11 | 每个演示的工具条上加一个「换亮暗」按钮：只把这块演示换成和整页相反的主题（局部 `data-theme`，DARK-REVIEW-PLAN D107 已经保证局部主题是一整张面）；整页切主题时它跟着重算。小程序标签页是 iframe，不跟 | 不用切整页就能看另一种主题下对不对。Gestalt 的「从右往左」我们不做，我们不支持从右往左排 |
| G12 | 「什么时候用 / 别用」73 个组件都要写；对错对照先写最容易用错的 12 个（按钮、对话框、提示条、轻提示、输入框、选择、开关、标签页、表格、空状态、徽标、菜单）；「文案」写 10 个有固定文字的（按钮、对话框、轻提示、提示条、输入框、空状态、确认两次、登录、标签页、菜单）。加测试：每个组件都有 `use` 和 `avoid`，中英条数一样 | 内容是这次的大头，结构做好但不写内容等于没学 |
| G13 | **顶栏和页面用同一套列**（2026-11-02 维护者：「很多东西都没有栅格化对齐的逻辑」）。顶栏是和 `.site-body` 一样的网格：侧栏列放品牌（页边 16）；正文列放栏目（从正文左线开始）和搜索框（右边停在正文右线）；目录列放四个图标，第一个的图形对齐目录的「本页」，最后一个对齐这一列的右边（页边 16）。≤ 1180 没有目录列，图标排在正文列最后、停在正文右线；≤ 820 回到一行、两头贴页边 16。侧栏第一个组名、正文第一行、目录「本页」离顶栏都是 32，在同一条横线上。顺带：列表的圆点画在正文线上（和勾、叉一样），代码块后面留 16 | 以前顶栏是一排 flex，各样东西的位置只看它前面有多宽，和下面的三列没有关系：搜索框右边、第一个图标都不在任何一条线上，侧栏比正文高 16。audit 冒烟逐个宽度量这些线 |
| G14 | **版面是一个居中的框**（2026-11-02 维护者：「宽屏下方版面空间没有很好利用，有点局促，感觉很不专业」）。侧栏 232 · 正文 · 目录 200 放进最宽 1680 的框，框在屏幕中间；正文列在框里伸缩（1440 宽时和以前一样）。顶栏的线和底色铺满屏幕，里面的东西用同一个框（`padding-inline`）。没有目录的页（组件总览、首页）正文占掉目录那一列 | 以前正文最宽 1200、整个靠左，1920 宽时右边空一条 300 多，2560 时空一半，看起来像没排完。居中的框是 Tailwind、Stripe 这类文档站的做法：两边留白一样，内容不会散得太开 |

## 3. 不学的

- **示意插图。** Gestalt 每个组件画一张绿色示意图。我们首页的组件墙已经是真组件，再画一套要维护两份。
- **「改属性」面板和全屏。** 我们的演示下面就是代码，复制即用；全屏对小组件没有意义。
- **团队支持栏目。** 我们是一个人的设计系统，「参与」在 README 和 CONTRIBUTING 里。
- **从右往左。** 不支持。

## 4. 验收

1. 任何一页左栏只有当前栏目的组；组件栏目第一项是「总览」。
2. 顶栏在 821–2600 宽排得下，中英两版都不溢出、不重叠（audit 冒烟检查逐个宽度量组件页）；≤ 820 抽屉最上面能切栏目。
3. `/components` 三个视图都能用键盘切换；状态表的「有 / 部分 / 没有」不只靠颜色（有字）。
4. 组件页滚动时右边目录高亮跟着走；演示的「换亮暗」只影响那一块。
5. 73 个组件都有「什么时候用 / 别用」；12 个有对错对照；10 个有文案。中英条数一致（测试）。
6. 全部门禁：xxd 单元测试、展示站 audit 全套、开源自查、Kumo 1458。
