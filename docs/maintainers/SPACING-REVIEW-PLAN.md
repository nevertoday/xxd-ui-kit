# 间距和对齐的体系（检测与修改）

> 2026-10-22。有人批评我们「间距的逻辑和对齐的逻辑不成体系」。这一轮先量，再定规则，再一项项改。
> 决定接着 CHART-REVIEW-PLAN 编号（D54 起），AI 先定，维护者可以改。做完在第 4 节打勾写日期。

---

## 0. 结论：批评是对的，问题不在「数」，在「规则」

设计师评审 V2 已经把数字收到了 4px 刻度上（门禁守着），所以单个数字挑不出毛病。缺的是三样东西：

1. **只有一把尺子，没有「哪种关系用哪一档」的规则。**
   - 组件 CSS 里一共写了 411 处间距：271 处直接写刻度（`--space-*`），只有 9 处用了有用途的名字（`--row-pad-x` 这类）。
   - 所以同一种关系各写各的。比如「容器到内容」：卡片 12，横幅、图表卡、统计、sheet、popover 16，对话框、面板 20。
     为什么是这个数，答不上来；紧凑密度下也只有一半跟着变。
2. **竖直方向按盒子算，不按看得见的算。**
   - 原则说「文字周围的垂直间距略小于水平间距」。实际上，padding 四边写一样的容器，看起来都是上下比左右宽 3–5px。
   - 原因是行高多出来的半行距。截图量墨迹：图表卡上 19、左 16.5；卡片上 15、左 12；统计上 20、左 16。
   - 反过来，padding 上下比左右少一档的几个（设置行、popover、菜单、对话框）看起来正好四边一样。
     对的做法已经有了，只是没写成规则。
3. **对齐没有写下来的规则，于是到处「差一点」。**
   - 分组小标题比框多缩 2px，行里的字缩 16px：两边都不对齐。
   - 关闭按钮的图标离右边 20–24px，内容离右边 16–20px。
   - 展示站的标志在 16，侧栏的字在 20；右上角 GitHub 图标离边 24，左边标志离边 16。
   - 正文里的二级缩进有三种：引用 18、代码块 16、列表 22.4。
   - 最先被看到的展示站自己不守规则：35 处间距不在 4px 刻度上（3、5、6、9、10、14px），18 处行高不是行高令牌（1.4、1.6、1.75，算出来是 24.5px 这种小数）。

门禁也只查「数在不在刻度上」，不查「关系对不对」「线齐不齐」。所以上面这些从来没被拦过。

## 1. 怎么测的

- **静态**：把 `packages/xxd-css/src/css` 里所有 padding / gap / margin 按属性和令牌统计，再按组件（容器、标题、行）分组对照；
  `xxd-site/public/site.css`、`xxd-mini/src/styles` 用同一套规则扫。
- **浏览器，148 个中文页 × 1280 / 390 宽**，在页面里量五件事：
  - 一摞竖排的东西里，各项内容的左边有没有「差 1–6px」；
  - 标题离上面近还是离下面近；
  - 容器到第一个内容的距离，按组件归类；
  - 一行里不同字号的字基线差多少；
  - 页面外框（标志、侧栏、搜索、正文、目录）的竖线。
- **墨迹**：对 16 种容器截图，把自己的边框、横穿的分隔线去掉，找第一处不是底色的像素。这是「看得见的」上下左右内边距。
- 截图逐张看：首页、设置组、横幅、设置页模板、资源列表模板。

## 2. 发现

严重度：**P0** 体系上的缺口，别人一眼就能指出来；**P1** 具体的不齐、不等；**P2** 打磨。

### A. 间距体系

- **A1 没有用途层**（P0）。见第 0 节第 1 条。容器内边距 12 / 16 / 20 没有规则；标题和说明之间是 2（设置行）/ 4（卡片、popover）/ 8（空状态）；
  组和组之间是 16（侧栏）/ 20（展示站侧栏）/ 32（设置页）。
- **A2 看得见的内边距上下比左右大**（P1）。墨迹实测（上 / 右 / 下 / 左）：

  | 容器 | padding | 看得见的 | 判断 |
  |---|---|---|---|
  | 卡片 `.xxd-card__body` | 12 | 15 / – / 16 / 12 | 上下大 3–4 |
  | 图表卡 | 16 | 19 / 16.5 / 21 / 16.5 | 上下大 3–5 |
  | 统计 | 16 | 20 / 17 / 17.5 / 16 | 上大 4 |
  | 面板 | 头 0·12·0·20，体 20 | 21 / 21 / 24.5 / 21 | 下大 3.5 |
  | sheet | 头 12·12·8·16，体 0·16·16 | 22 / 24 / 20.5 / 16.5 | 上大 5.5，右边是关闭按钮 |
  | 横幅 | 12 / 16 | 13 / 14.5 / 16.5 / 16 | 上下差 3.5 |
  | 设置行 | 12 / 16 | 16 / 16 / 16.5 / 16.5 | ✓ |
  | popover | 12 / 16 | 16 / – / 16.5 / 17 | ✓ |
  | 对话框 | 头 16·20，尾 20 | 20.5 / 20 / 20 / 20.5 | ✓ |
  | 菜单 | 4 + 行 | 15 / 17 / 14 / 17.5 | ✓ |

- **A3 紧凑密度只收了控件**（P1）。紧凑密度下控件高度、行内边距跟着变；卡片、横幅、对话框、面板、图表卡的内边距不变。
  360px 宽的侧边栏里，对话框仍然留 20。
- **A4 小程序和展示站不在门禁里**（P1）。小程序样式有 6、10、2、36、40 这些字面值；展示站见 C1。

### B. 对齐

- **B1 分组小标题比框多缩 2px**（P1）。`.xxd-group__title { padding: 0 2px }`：既不对齐框（0），也不对齐行里的字（16）。正是「差一点」。
- **B2 关闭按钮的图标没对齐内容右边**（P1）。
  - 头部右边距一律写 12，没管按钮多大：sheet 的图标离右边 20（内容 16），面板 24（内容 20）。
  - 横幅的关闭用 `margin: -4px -6px -4px auto` 这种算好的数。
- **B3 展示站外框的竖线不齐**（P1）。
  - 标志 16，侧栏的字 20，差 4px。
  - 右上角最后一个是幽灵按钮，图标离右边 24，左边标志离边 16：左右页边不一样。
  - 搜索框从 129.5 开始，不在任何一条竖线上。
- **B4 正文的二级缩进有三种**（P2）。引用 18（2 + 16）、列表 22.4（1.4em，不在刻度上）、代码块 16（框里的字，这个对）。
- **B5 横幅里竖直对齐没有说法**（P2）。图标对第一行的中线；关闭按钮用 −4px 硬拉，中线比第一行高 2px；操作按钮的上沿和第一行的上沿对齐。
  后两种都说得通，但没写下来，下一个组件就会再发明一种。
- **B6 演示框的工具条比代码多缩 2px**（P2）。工具条字在 14，代码字在 16；表格的单元格 10 和规格表 12 也不一样。

### C. 展示站（别人最先看到的）

- **C1 自己不守规则**（P0）。
  - 35 处间距不在 4px 刻度上：导航 `5px 8px`、目录 `3px 0`、演示工具条 `6px 8px 6px 14px`、代码 `14px`、属性表 `8px 10px`……
  - 18 处行高是倍数（1.4 / 1.6 / 1.7 / 1.75），算出来是 22.4、24.5 这种不在 4px 网格上的数。
  - 原因：`design-scale.test.mjs` 只扫 `packages/xxd-css`。
- **C2 节奏的数是随手写的**（P2）。标题下 12、段落下 12、规则列表下 16、演示框下 20、代码块之间 12。
  看起来差不多，但说不出为什么是 16 和 20 两个数。

### D. 门禁

- **D1 只查数，不查关系**（P0）。没有一项检查会因为「标题差 2px 没对齐」「上下看起来比左右宽」「关闭图标不在内容右边那条线上」而失败。

## 3. 决定

- **D54 间距分两层：刻度 + 用途。** 组件写用途名，刻度只给用途令牌和光学微调用。新令牌（tokens.css，紧凑密度一起收一档）：

  | 用途 | 令牌 | 标准 | 紧凑 | 用在哪 |
  |---|---|---|---|---|
  | 容器内边距·小 | `--inset-sm` | 12 | 8 | 卡片、表格格子、输入框类 |
  | 容器内边距·中 | `--inset-md` | 16 | 12 | 一块内容：横幅、图表卡、统计、设置行、popover、toast、sheet |
  | 容器内边距·大 | `--inset-lg` | 20 | 16 | 一整个任务面：对话框、右侧面板 |
  | 同一件东西的部件 | `--gap-tight` | 4 | 4 | 标题和说明、数字和单位 |
  | 并列的同类 | `--gap-items` | 8 | 8 | 按钮之间、chip 之间、图例 |
  | 一组里的块 | `--gap-block` | 16 | 12 | 卡片头和图、字段之间 |
  | 组和组之间 | `--gap-group` | 32 | 24 | 设置组之间、展示站的节 |

  选内边距只看「这是什么容器」，不看它多宽。原来的 `--row-pad-x`、`--control-pad-x` 这些照旧，它们是控件自己的尺寸。
- **D55 看得见的四边相等**：文字开头的容器，`padding-block` 比 `padding-inline` 小一档（`--inset-md` 写成 12 / 16，`--inset-lg` 写成 16 / 20）。
  行高多出来的半行距（3–4px）正好补上，看起来四边一样。这就是原则 §6「垂直略小于水平」的具体写法。
  只有图、按钮这种没有半行距的东西贴边时，才写成一样。
- **D56 紧凑密度也收容器**：`--inset-*` 和 `--gap-block` / `--gap-group` 在紧凑密度下小一档（上表）。
- **D57 对齐只有两条线**：
  - **外线**：框、分隔线、整行宽的控件的边。框外面的字（分组小标题、节标题、说明）贴外线。
  - **内线**：外线 + 容器内边距。框里面的字贴内线。
  - 两条线之间不许出现第三条（「差 1–3px」）。二级缩进（列表、引用）统一 `--space-5`（20）。
- **D58 幽灵图标按钮按图标对齐，不按按钮框**：关闭、更多这类放在角上的按钮，外边距 = 容器内边距 −（按钮 − 图标）/ 2。
  这样图标的边正好落在内线上。用 `calc()` 和令牌写，不写算好的数。展示站右上角同理。
  一排按钮里的幽灵按钮不改：它悬停时有底色，底色出现的地方才是它的边。
- **D59 和多行字同排时怎么竖直对齐**：
  - 比一行矮的（图标、关闭按钮）对齐第一行的中线：上下让出（行高 − 按钮）/ 2。
  - 比一行高的（按钮）上沿对齐第一行的上沿。
  - 设置行这种「整行一件事」的，照旧整块居中。
- **D60 展示站和小程序也进门禁**：同一套刻度检查（间距只用令牌、行高只用行高令牌、不用已经去掉的 15px、二级缩进不按 em 算）扫 `site.css` 和小程序样式。新加两项检查：
  - **「差一点没对齐」**：一摞竖排的字，左边差 0.5–3px 的报出来。
  - **「看得见的内边距」**（audit `--only=inset`）：给 11 种容器截图量墨迹，标准和紧凑各一遍。上下差不超过 5px；上下都不比左边大 3px 以上。
    横幅上面是 14px 的标题、下面是 12px 的说明，两行的半行距不一样，量出来上下差 4.5px，所以门槛是 5 不是 4。

### 复查时发现的

- **图表卡头和图之间 12 → 16、设置组之间 24 → 32**：是按 D54 的表改的，看起来稍松。
- **首页组件墙在「英文 · 圆角 · 紧凑」下留了一格洞**：格子变矮，排法挤出一个四面都是最矮格子的洞。

## 5. 没改的

- **Kumo 来的 React 组件**（不在 HTML / React 对照表里的那些）仍然是 Tailwind 的刻度（10、14px……）。
  它们是上游代码，改了合并上游会很痛。对照表里的组件已经由 parity 门禁对齐到 HTML 版。
- **一排按钮里的幽灵按钮**看起来间隔大一点（D58 的理由）。
- **首页两个并排的模板框内边距不同**：左边是 360 宽的侧边栏，按紧凑密度排，本来就该更紧。
- **展示站自己的现场混色**（代码底色是主色 4% 混白，8 处）：色阶里没有对应的用途名，要先定颜色。这一轮只管间距，不动它。
- **展示站外框的断点**（1180 收起目录、820 收起侧栏）：这是站的版式，不是组件，不受「只有三个断点」管。
- **组件里的间隔（gap）大多仍写刻度**：门禁只要求容器的内边距写用途令牌。
  部件、同类之间的间隔多数本来就是 4、8，改名不改样子；以后动到哪个组件就顺手换。
