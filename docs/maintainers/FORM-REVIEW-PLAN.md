# 表单和出错状态（对抗测试）

> 2026-10-23。接着 TRUNCATION-REVIEW-PLAN 编号（D97 起），AI 先定，维护者可以改。做完在第 4 节打勾写日期。

---

## 0. 结论

- **一个普通输入框出错是对的**：红边、出错又聚焦红边加粗、错误文字连进 `aria-describedby`。
- **坏在「普通输入框以外」和「一整张表单」**：
  1. `Xxd.setFieldError` 只认识普通输入框。别的控件上，错误文字被塞进框里（输入组、标签输入），或者塞进 `<label>` 里变成控件名字的一部分（选择、复选、单选、开关）；框也不变红。
  2. 有的控件出错时根本没有出错的样子：开关、标签输入；自定义下拉出错又聚焦时，里面那 1px 是墨色。
  3. 出错只靠颜色：错误文字和说明只差颜色（红绿色弱看不出）；高对比度模式下出错的框和普通框一模一样。
  4. 没有「整张表单」的做法：写 `required` 就是浏览器自己的气泡（语言跟浏览器走，中文页面里冒英文）；提交后没人把焦点带到第一个错，改对了也没人清掉错误。
  5. 中文输入法打字时按回车选字，下拉（combobox）当成「选中这一项」；搜索框按 Esc 退出输入法，把字也清空了。

## 1. 怎么测的

- 每种表单控件（输入框、多行、选择、裸选择、输入组、密钥输入、复选、单选、开关、标签输入、combobox、自定义下拉、日期）放进字段里：
  - 用 `Xxd.setFieldError` 标错，看错误文字在哪、在不在 label 里、在不在框下面，框变没变红；
  - 照文档把 `aria-invalid` 写在该写的地方，再聚焦，看边和里面那 1px；
  - 高对比度（forced-colors）下比出错的框和普通框；
  - 作者自己写了一行 `.xxd-error`，再调 `setFieldError` 设、清。
- 原生 `required` 提交；输入法组合中（`isComposing`）按回车 / Esc；暗色下的日期框；React 对照页加出错的一对。

## 3. 决定

- **D97 错误放在整个控件下面，不进框、不进 label**：
  - `setFieldError` 先找控件「看得见的那个框」：输入组、标签输入、自定义下拉、选择外面那层、combobox、选项（`.xxd-choice`）、区间滑块；错误放在它后面；
  - 单选按组标错：一组里每个单选都写 `aria-invalid`、连上同一行错误，错误放在组的最后；
  - 作者已经写了的错误（字段里的 `.xxd-error`）就用它，不再加第二行；清的时候作者那行藏起来（`hidden`），自己加的删掉；
  - 设置行（`.xxd-row`）里的控件，错误写在左边那一栏的说明下面；包着控件的别的 `<label>`（分页的「每页」）错误放在它后面；
  - 不在字段里的控件，错误紧跟在后面（要放在下面就包一层 `.xxd-field`）。
- **D98 每种控件出错都是红边，出错又聚焦都是红边 2px**：
  - 外面的框认里面的控件：`.xxd-input-group / .xxd-taginput / .xxd-picker` 里的控件出错，整个框变红；
  - 开关出错红边；自定义下拉、裸选择出错又聚焦，里面那 1px 也是红的。
  - 状态优先级不变：禁用 > 出错。
- **D99 出错不只靠颜色**：
  - 错误文字前面一个危险图标（圆里一个叹号，和 toast 的危险图标同一个），图标和文字第一行对齐；
  - 高对比度下：出错的框加粗成 2px（画在里面），图标保留系统色。
- **D100 出错时错误顶替说明，字数留着**（三种实现一样）：
  - 错误文字自己写清楚怎么改，说明里的规则要写进错误里（「至少 8 位，还差 3 位」）；
  - 页面不多跳一行；读屏只念一句。
- **D101 整张表单：`<form data-xxd-validate>`**：
  - 不用浏览器的气泡（写 `novalidate`），用 `required`、`type`、`minlength`、`pattern`、`min / max`、`data-max` 这些原生约束；
  - 提交时：每个错都标在字段下面，焦点到第一个错，错了几处念一句；有错时提交事件不往下传（作者的提交处理只在全对时才跑）；
  - 错误文字：元素上 `data-error-<种类>` / `data-error` 优先，否则用三语的默认句子，带上字段名和差多少（「至少 8 个字，还差 3 个」）；
  - 改对了马上清掉；没改对不催（打字时不新加错误，下次提交再说）；
  - 邮箱、网址、电话里的全角字母数字和「＠」「。」先换成半角再校验（D104）；
  - API：`Xxd.validateForm(form)` 返回出错的控件列表；服务器回来的错照样用 `setFieldError`。
- **D102 字数会动**：`.xxd-help[data-counter]` 跟着同一个字段里的输入框更新，按字（emoji 算一个）数；
  - `data-max` 是软上限：超了数字变红，提交时算错；`maxlength` 是硬上限（浏览器拦）；
  - 超出时念一次「超出 N 个字」，不是每个字都念。
- **D103 输入法组合中按的键不算**：回车、Esc、方向键在 `isComposing`（或 keyCode 229）时都交给输入法：combobox、命令面板、搜索框、标签输入、需要输入名字的删除确认、浮层的 Esc。
- **D104 全角换半角**：只在邮箱、网址、电话里换，换完写回输入框（这是用户本来想打的）。
- **D105 React 一样**：对照页加「字段出错」「复选出错」两对，比标签、边、错误文字的字号颜色和图标。
  - 绑定层对齐样式；`aria-invalid` 是属性，CSS 加不上：Kumo 的 Field 在错误一直显示时写 `invalid`，Checkbox 的 `variant="error"` 写 `aria-invalid`（这一处改了上游源码，只加属性）。
  - React 能打字的框聚焦时也是边 + 里面 1px（以前只有 1px）。
- **D106 门禁**：audit 加 `--only=form`：
  - 组件页每个表单控件标错：错误在控件下面、不在 label 和框里，看得见的框变红，出错又聚焦红边 2px，高对比度下和普通的不一样；
  - 一张演示表单：空着提交，焦点到第一个错、每个错都在、说明被顶替；改对后错误消失；输入法组合中回车不选中。

## 5. 没改的

- **自动填充的底色**：Chrome 自动填充时把输入框涂成浅蓝（输入组里是框里一块蓝）。要盖住只能用很大的 inset 阴影，和聚焦的 inset 1px 打架；暗色下浏览器自己会用暗的那一档，先不管。
- **错误汇总**：长表单（十几个字段）顶上一个「这几处要改」的列表（GOV.UK 的做法）。我们的表单都短，焦点到第一个错 + 念出几处就够；以后有长表单再加。
- **自定义下拉、标签输入的「必填」**：它们不是原生控件，没有 `required` 约束；要校验就在提交时自己调 `setFieldError`。
- **小程序**：每个错误都是 `role=alert`，一次提交出好几个错会连着打断播报；小程序的读屏支持本来就弱，先不改。开关在小程序里没有 `invalid`。
- **React 的说明**：Kumo 出错时把说明换成错误，和我们一样；但 Kumo 没有字数，React 版要字数得自己写。
- **不在字段里的控件**：错误紧跟在控件后面，在一行里的布局（演示里单放的复选框）会排在旁边；要放下面就包一层 `.xxd-field`。
