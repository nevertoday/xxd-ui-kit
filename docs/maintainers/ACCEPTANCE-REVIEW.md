## 1. 各条发现和处理

### State Completeness（state）

现状：单一状态大多齐全，但「两个状态同时成立谁赢」全仓库没有写，全靠选择器优先级碰运气。

281 个叠加用例在亮、暗两套外观下跑过，下面每条都用真鼠标、真键盘复现过。

- **P0 裸下拉（设置行推荐的写法）键盘聚焦时没有任何记号**（WCAG 2.4.7）→ 聚焦时露出 `--action` 的边（2px），出错时露出红边。
- **P1 选中 + 悬停，选中样式丢了**（列表、表格、卡片；小程序同一份 CSS）→ 悬停规则排除选中 / 当前的。
- **P1 幽灵、描边按钮的 `aria-pressed` 被变体盖掉**（展示站代码区的「折行」按了没反应）→ 按下的规则写到变体后面；实心按钮按下用深一档的底。
- **P1 缺禁用**：
  - 分段、tab、chip、链接、输入组补上禁用；
  - 自定义下拉改用禁用令牌；
  - 裸下拉禁用后悬停不再变色；
  - 工具条禁用项悬停不出淡底。
- **P1 出错 + 聚焦**：以前聚焦盖掉红边，或者看不出聚焦了 → 出错又聚焦时红边加粗成 2px。
- **P2 进行中的按钮还有悬停和按下反馈**：现在和禁用一样，都不变（和小程序一致）。
- **状态优先级写进设计原则 §9**：禁用 > 进行中 > 出错 > 选中 / 当前 > 键盘焦点 > 按下 > 悬停 > 默认。
  - 焦点和出错同时成立时两样都看得见；
  - 选中的在悬停时保持选中。

### Interaction Predictability（predict）

结论：**不通过**。

- **P0 面板 / sheet 开着时再开确认框**：
  - Tab 卡在「取消」上；Esc 关掉的是后面那一层，确认框还开着；第二下 Esc 后焦点掉到 body。
  - 原因：面板的焦点陷阱和 Esc 不知道上面还有原生模态对话框。
  - 改成：焦点在开着的模态对话框里时，面板让开。
- **P1 面板里的下拉、组合框、拖动排序按 Esc 关掉整层** → 面板的 Esc 最后处理，里面的组件先拿到 Esc。
- **P1 打开浮层的按钮被删掉（删除那一行）后，焦点掉到 body** → 退回到下面一层或正文。
- **P1 对话框开着时出 toast，「撤销」点不到** → 没指定位置的 toast 放进最上面那个模态对话框里。
- **P1 排序：键盘拿起后 Tab 走了，一直停在「拿起」** → 焦点离开就当放下，顺序变了照样派发 `xxd:change`。拖动中 Esc 放回原来的顺序。
- **P1 两次确认：双击直接删掉了** → 双击的第二下不算；Esc 退回。
- **P1 导入设置直接覆盖、没有撤销** → 覆盖前存一份，toast 里给「撤销」。
- **P1 进行中再点，`runBusy` 返回 undefined**：会员页「我已支付」连点两下，马上弹「已开通」→ 返回正在跑的那个任务。
- **P2 开着两个面板时先关下面那个，上面那个背后不再是 inert** → 关掉一层后，最上面那层重新设一次。
- **P2 对话框开着时背后的页面跟着滚** → 模态对话框开着时锁住页面滚动，留出滚动条的位置。
- **P2 小程序带「撤销」的 toast 只有 5 秒** → 和网页同一条规则（10 秒）。

### Accessibility（a11y）

99 页只用键盘走过，没有键盘陷阱；组件的键盘模型（APG）基本都对；点按区、放大 200%、文字间距、悬停内容、状态播报都通过。没过的：

- **P1 面包屑聚焦完全看不见、tab 的焦点环只剩一条竖线**（被 `overflow` 裁掉，86 页受影响）→ 这类焦点环画在元素里面（`outline-offset: -2px`）。
  代码块、可点的设置行同样处理。
- **P1 出错的输入框聚焦后外观不变** → 见上（出错 + 聚焦）。
- **P1 「可点的列表行」是 `<li>` 加指针，键盘到不了** → 正文区写成 `<button class="xxd-list__main">`，点的范围铺满整行，焦点画在整行上。
  组件示例、侧边栏模板一起改。
- **P1 拖动排序没有单指针替代**（WCAG 2.2 的 2.5.7）→ 单击把手拿起，旁边出现「上移 / 下移」；再点一下把手放下。
- **P2 输入框的焦点只是 1px 边变色**（暗色主色下只差 1.4:1）→ 输入框、下拉、选择器、标签输入、输入组聚焦一律 2px（还是一个框）。
- **P2 侧栏折叠按钮一开始没有 `aria-expanded`**，名字也会变 → 初始化时就设好。
- **P2 320 宽的横向滚动**：规则列表里的长令牌名、工具页的表格 → 窄屏可以断开；正文表格自己横着滚。

### Token Consistency（token）

原生组件在异常令牌值下整体都跟着变，Shadow 版和普通版一致。没跟上的：

- **P1 React（Kumo）组件在局部暗色块里仍是亮色**：语义变量只在 `:root` 上算一次。
  改了 Kumo 主题生成器，在局部 `[data-theme]` 上重新算；验证过亮暗两套的 54 个变量都相同。
- **P1 局部暗色块里的 tooltip 用的是整页外观** → 提示跟着锚点所在那一块。
- **P1 主色 + 局部暗色块，开关「开」是米色**（漏了一个声明）→ 补上。
- **P1 主色 + 高对比**：局部亮 / 暗块的线还是淡线 → 高对比的媒体查询补上主色块的选择器。
- **P1 `--control-h` 改了，图标按钮不跟；菜单项写死 32** → `--icon-button: var(--control-h)`，菜单项、选项用 `--control-h-sm`。
- **P2**：
  - 写死的 100ms → `--motion-out`；
  - 实心徽标的 `#fff` → `--*-on`；
  - 局部 `data-corners` 不生效 → 现在页面里的一块也能单独圆角 / 直角。

### Extensibility（extend）

文档里改组件外观的行内样式只有 22 处，组件上没有 `!important`。修掉的 P1：

- 图卡放进等高网格内容被拉开 → `align-content: start`。
- React 分段的 `size="sm"` 不起作用 → 分段有了 sm / lg 两档。
- `data-optional` 只写属性不写值时什么都不显示 → 按语言显示「可选 / 選填 / Optional」。
- 头像只能写没进文档的 `--avatar-size` → 加 `data-size="sm | lg"`。

### Visual Integrity（visual）

改外观不会让排版错位：暗 + 圆角 + 紧凑 + 立体 + 自定义蓝，在 1280 / 390 下 101 页和缺省外观比，细节检查没多出问题。
对话框、sheet、面板在 740×360、320×256 都在视口里，按钮能滚到；2560 宽不溢出。没过的：

- **P0 宽 ≤ 820（桌面放大到 200% 也会进这个状态）时，关着的抽屉导航里 150 个链接还在 Tab 顺序里**，焦点落到屏幕外 → 关着时 `visibility: hidden`（收起动画放完再藏）。
- **P1 颜色页整页能横着拖 178px**（只给读屏的字在横向滚动区外面定位）→ 滚动区自己做定位的基准。
- **P1 320 宽整页横向溢出**（更新日志、工具页的表格、开关页）→ 规则列表里的长令牌名窄屏可以断开；正文表格自己横着滚。
- **P1 toast 收起叠放时后面那张的字露出来、压在一起** → 后面几张只露出边，字藏起来。
- 列进后续（见第 3 节）：
  - 按钮里放不下的长字被两边硬裁；
  - 被省略号吃掉的关键信息没有办法看全文（dock 状态里的数字、命令）；
  - 小程序 280 宽时百格图的图例名被截掉；
  - 大字号下的量表标签、热力格星期标签。

### Regression Safety（regress）

做法：故意做 20 个「看着小、其实是回归」的改动（变异），看现有防线拦住几个。

- **CI 里的门禁拦住 15 / 20**。其中 8 个是两种实现对照（parity）碰巧拦住的：只改了 HTML，React 没跟着变。
  改令牌（两边一起变）、改共用的类、改悬停 / 聚焦这类状态，基本漏掉。
- 各道防线单独拦住的数量：
  - 单元测试 5 / 20：查「写法守不守规矩」，不查「数值对不对」；
  - audit 12 / 20；
  - 截图（新基线）16 / 20；
  - 样式快照原型 15 / 19。CI 加上它是 19 / 20。
- 漏掉的 5 个：
  - 焦点环没了；
  - 暗色 `--line` 变亮；
  - 遮罩的层级低于 dock；
  - 主按钮悬停不变色；
  - 吸顶表头透明：站上没有任何演示用了 `data-sticky-head`。
- **P0 截图基线完全失效**：10-13 截的 192 页，现在 296 页，24 / 24 张都报「尺寸变了」。新基线连跑两次，也有 1–2 张超过噪声门槛（不确定进度条），所以截图回归现在不能用。
- **P1 文档登记的属性里有 16 / 104 个从没出现在任何演示里**（`data-sticky-head`、`data-wrap`、`data-collapsed`、`data-light-dismiss`……），哪道门禁都看不到。
- **P2 外观覆盖偏窄**：contrast 只跑直角、标准密度；规格表的圆角样品写死了数值。

这一轮做了的：`--only=motion`（按下）、`--only=states`（悬停叠在选中 / 禁用上、出错 + 聚焦）、`--only=focus`（焦点环被裁），补上了「交互状态没人看」的一部分。

## 2. 新门禁

| audit | 查什么 | 来源 |
|---|---|---|
| `--only=focus` | 每个能 Tab 到的东西，焦点环不被祖先的 `overflow` 裁掉两边以上 | a11y 的 ringclip |
| `--only=motion` | 按下的同一刻有看得见的变化；减少动效下只剩慢淡入淡出，进行中的按钮不定住 | 动效这一轮 |
| `--only=states` | 选中 / 当前 / 按下叠上悬停时选中记号不变；禁用的悬停不变；出错又聚焦时边还是出错色 | state 的 combos |

单元测试改了的：原样模式、圆角块、hover 清零表、控件的边（出错 + 聚焦）、小程序 toast 时长，都按新的约定改。

## 3. 没改的（后续）

- **小程序 H5 不能用键盘**：
  - 微信小程序本身没有键盘操作，H5 只是展示站里的预览；
  - 要支持得给 Taro 的 View 加 tabindex 和 Enter / 空格处理，这一轮不做。
- **网页版缺 Steps、Uploader、Result、「已选 N 项」选择条**（小程序有）。还有三种实现的属性命名不统一：
  - 危险：HTML 是 danger，React 是 destructive / error；
  - 缺省尺寸写法不一。
  - 要出一张对照表，React 接受 danger 作别名。这些是新组件和 API 的活，单独排期。
- **React 对话框本身没有内边距**（演示里各写各的 p-5 / p-6）：
  直接加默认内边距会让现有用法加倍，要先改演示再改默认。
- **Kumo 的写死尺寸**（工具条 30 / 26 / 36、表头 36、表格行 44）和小程序 `Stack` 的数字 gap：属于 P2，跟着以后动到这些组件时改。
- **React Tabs 是手动激活、原生是自动激活**：两种都符合 APG。统一要改 React 的行为，可能影响用户代码，先不动。
- ~~**截断以后看不到全文**、**按钮里的长字被两边硬裁**（visual P1）~~：2026-10-22 在 `TRUNCATION-REVIEW-PLAN.md` 做了（内容折行、标签省略在末尾、悬停 / 聚焦提示全文）。
- **窄屏的零碎**（visual P2）：工具页对照区里 Kumo 输入框 320 宽多 8px；窄屏 Shift+Tab 回到「打开导航」时页面跳一下；菜单在 320×256 下伸出视口底边 4px；/components/appearance/ 280 宽多 13px（没找到元素）。
- **小程序窄屏的图例、大字号下的标签**：图例换到格子下面、量表标签允许两行，下一轮跟小程序真机检查一起做。
- **回归防线**（regress，按收益排）：
  1. 样式快照门禁：组件页、模式页里每个 xxd 元素的计算样式 × 4 种外观 × 默认 / 悬停 / 聚焦 / 按下，差异直接读得懂（「padding-left 16px → 12px」）。原型实测约 3.7 分钟、基线 4.7 MB。先修动画抖动。
  2. 给那 16 个没演示的属性各加一个演示，属性覆盖检查进展示站测试。
  3. 截图回归：冻结所有 `@keyframes`，改成逐个演示截图、基线由 CI 生成；做不到就删掉。
  4. contrast、截图各加一个紧凑密度；小程序 check-h5 进 CI。
  5. 拿这 20 个变异定期跑「门禁的门禁」，确认拦截率不往下掉。
- **首页组件墙按列排**，Tab 顺序在第 33 格以后跳回去：这是瀑布墙的排法。改成按行排会让墙变稀，先不动。
