# 操作反馈和按钮对齐

> 2026-11-11。接着 LEADING-REVIEW-PLAN 编号（D171 起），AI 先定，维护者可以改。做完在第 4 节打勾写日期。
> 维护者问了两件事：交付行为的反馈和状态能不能更好；按钮和文字的对齐是不是忽略了细节。

---

## 0. 结论

- **反馈**：网页版基本守住了 §8、§9（MOTION-REVIEW-PLAN D82–D90）。React（Kumo、xxd-react）和小程序没跟上，
  而且没有一个门禁会「点一下，过一会儿看用户看到了什么」，React 演示又是藏着、不能点的，所以这一层从来没被测过。
- **对齐**：按钮里面是齐的（中文字比框中心高 0.2–0.7px，图标和字差 0.3–0.5px，React 和 HTML 差 ≤ 0.5px）。
  看起来不齐的是两条规则：
  1. D59「比一行高的按钮上沿对齐第一行」：横幅里 32 高的按钮挨着 20 高的标题，按钮的字比标题低 6.5px，正好落在标题和说明中间，和哪一行都不齐；页面标题旁的按钮低 2.3–3.5px。
  2. 「整块居中」：设置行、列表行、账户行、状态条、导入导出把按钮放在标题 + 说明的正中间，比标题低 10–12px；说明折三行时低 22px。设置行写了这条，其他几种没写也这么做。
- 门禁：「细节」不查按钮和旁边的字是不是在一条线上。

## 1. 怎么测的

- **对齐**：198 页（组件、模式、模板、首页，中英），1280 / 390，HTML 和 React 演示。
  量墨迹不量盒子：只把目标的字设透明再截一次图，变了的行就是它的墨迹（2 倍图）；基线用 0×0 的 inline-block 探针。
  西文按基线以上的墨迹算中心，排除 p、y 这种下伸字母的 1–1.5px。脚本和原始数据在会话草稿目录 `align/`。

  按下、进行中、完成、toast 时长、焦点在哪、读屏播报。网页版的模式页、组件页同样点一遍。

## 3. 决定

### 对齐

- **D171 和字同排的控件，字对齐那一段字第一行的中线**（取代 D59 的两句）：
  - 不管控件比一行高还是矮，都让控件的中线对齐第一行的中线：控件往上让出（行高 − 控件高）/ 2，比一行高时这个数是负的，伸出去一样多。
    用令牌和 `calc()` 写，不写算好的数。
  - 设置行、列表行、账户行、状态条、横幅、页面标题都照这条：说明折几行，控件都和标题在一条线上。
  - 字只有一行时，和以前的居中一样。
  - 「…」这种贴着基线画的字形不算（基线对齐就是对的）。
- **D172 门禁「控件和标题不在一条线」**：「细节」里加一项。控件的字（没有字的量控件本身）的中线和旁边那段字第一行的中线差 > 1.5px 报出来；HTML 和 React 演示都查。
- **D173** React 底部栏演示补 `size="sm"`；表格复选框对齐格子第一行。

### 反馈

- **D174 React 和小程序守同样的进行中 / 完成 / toast 规则**（D84–D88 补到 React 和小程序）：
  - Kumo `Button loading`：`aria-busy`，不写 `disabled`（焦点不掉）；看得见的进行中晚 150ms；字保留但透明、转圈居中，宽度不跳；减少动效下转圈慢淡入淡出。
  - xxd-react 给一个和 `runBusy` 同样行为的钩子（进行中、完成的勾 1 秒、失败），React 演示用它。
  - Kumo toast 的时长按 D87 算（告知按字数、出错至少 6 秒且 assertive、带操作 10 秒），悬停、聚焦、后台时暂停。
  - 小程序按钮完成时打勾；toast 在页面隐藏时暂停。
- **D175 复制失败要看得见**：每一层复制失败都显示「复制失败」（toast 或按钮上的状态），备用路径失败不能说成功；焦点留在原处。
- **D176 失败要看得见、能重试、读屏听得到**：
  - `runBusy` 的任务失败：出错的 toast（至少 6 秒），带「重试」，重试就是再跑一次同一个任务；焦点留在按钮上。
  - 成功和失败都进 live region（成功 polite、失败 assertive）。
- **D177 设置的保存状态**：
  - 改了马上存的设置（开关、复选、下拉），存的时候说「保存中」、存好说「已保存」、存不进去就把控件退回原来的值并说「没有保存，重试」。
    写在底部状态条（有的话）或设置行下面，用 live region。
  - 设置页的演示里写明「改动自动保存」（§11）。
- **D178 焦点不掉到 body**：一个操作把有焦点的东西删掉、藏起来或禁用以后，焦点移到它的结果（新出现的那一项）、同组下一个能用的控件，或者所在的容器（`tabindex="-1"`）。
- **D179 React 两次确认和 HTML 一样**：第二次点击和第一次隔得太近（双击）不算；Esc 退回；进入确认时播报「再按一次」；聚焦或悬停时不复原。
- **D180 每个演示的主操作都要有结果**：点了什么都不发生的演示补上结果（toast、状态、跳过去）。
  会员付完变成已开通；拖放区「选择文件」打开选择框，类型不对说清楚；导出在真的开始下载后才说「已导出」；导入 0 项说「没有可导入的设置」，不给撤销。
  删除优先「删掉 + 撤销」，两次确认只给撤不回来的（§9「偏好可撤销」）。链接上的 `runBusy` 也有进行中和完成的样子。
- **D181 禁用要说为什么**：能不禁用就不禁用（点了再说缺什么）；必须禁用时，旁边一行字或 tooltip 说原因（`aria-describedby`）。
- **D182 门禁「点了有没有结果」**（audit `--only=feedback`）：
  - 组件页、模式页每个演示的操作（HTML 和 React）点一下，在 0 / 100 / 1100 / 3000ms 取样；
  - 1.1 秒内看不到任何变化、焦点掉到 body、toast 时长不在 D87 的范围、进行中在 150ms 前就露出来，都报出来；
  - React 的按钮演示改成能点的（点一下进入进行中再完成），不再是一个定住的 `loading`。
