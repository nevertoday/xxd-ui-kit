# 动效和交互反馈（对抗测试）

> 2026-10-22。接着 COLOR-REVIEW-PLAN 编号（D82 起），AI 先定，维护者可以改。做完在第 4 节打勾写日期。
> 同一轮还按 7 条验收指标做了多 agent 核查，结论和修改在 `ACCEPTANCE-REVIEW.md`。

## 0. 结论

- **动效本身守规矩**：
  - 87 处 transition / animation 全部只动 opacity、transform 和颜色，没有一处动布局，没有 `transition: all`；
  - 悬停进入立即变（32 种元素都实测过）；
  - JS 驱动的动画（拖动排序、庆祝、滚动文字）都看「减少动效」；没有平滑滚动。
- **坏在反馈**：
  1. **按下的反馈慢，而且很多东西根本没有**：
     - 按钮按下的底色要淡入 140ms，快速点一下（< 100ms）几乎看不到；小程序按钮也是这样；
     - 工具条、菜单项、侧栏项、chip、链接、卡片链接、排序表头、拖动把手、下拉触发器、面包屑「…」、行内复制、符号面板、命令面板选项，按下时什么都不变。
     - 桌面上有悬停兜着，手机上点下去要等结果出来才知道点到了没有。
  2. **进行中、完成的反馈有洞**：
     - 减少动效下进行中的按钮只剩一段不动的弧（字是透明的），像卡死了；
     - 很快的操作会让字闪一下；
     - 没有图标的按钮完成后没有任何反馈。
  3. **toast 的时长不看内容**：一律 2.6 秒，40 个字的提示和出错信息也是；页面在后台时照样计时，切回来已经没了。
  4. **复制的备用路径丢焦点**：剪贴板接口不能用时，焦点会掉到 body 上。

## 1. 怎么测的

- **静态**：网页、小程序、展示站样式里全部 transition / animation / keyframes，查动的属性、时长和缓动是不是令牌、有没有 `transition: all`。
- **按下 / 悬停**：组件页、模式页演示里每个能点的东西（32 种），用 Chrome 开发者协议强制 :active、:hover。
  分别在强制的同一刻和 260ms 后读计算样式，区分三种情况：「没有变化」、「慢慢变」（有过渡，快点击看不到）和「立即变」。
- **减少动效**：模拟 `prefers-reduced-motion: reduce`，列出每页还在跑的动画；看进行中的按钮。
- **读实现**：`runBusy`（进行中 → 完成）、`toast`（时长、暂停）、复制（成功、失败、备用路径）、`reducedMotion()` 的调用点。

## 2. 发现

严重度：**P0** 手机上感觉「没点到」；**P1** 反馈缺了或会误导；**P2** 打磨。

| # | 发现 | 严重度 |
|---|---|---|
| M1 | 按钮（各变体、小程序也是）按下的底色淡入 140ms，快速点一下看不到 | P0 |
| M2 | 二十多种能点的东西没有按下样式（见第 0 节） | P1 |
| M3 | 减少动效下进行中的按钮：字透明 + 转圈定住，只剩一段不动的弧。单独的转圈和加载条已经换成慢淡入淡出，按钮里的漏了 | P1 |
| M4 | 进行中立刻显示：< 150ms 的操作字会闪一下 | P2 |
| M5 | 没有图标的按钮完成后没有反馈（勾只替换已有的图标） | P1 |
| M6 | toast 一律 2.6 秒，不按字数；出错的也是 2.6 秒；页面在后台时照样计时 | P1 |
| M7 | 复制的备用路径（`execCommand`）把焦点移到临时文本框后删掉，焦点掉到 body | P1 |
| M8 | 原则 §8 写「减少动效：没有组件例外」，实现里转圈、加载条有慢淡入淡出的例外（这是对的），文档和实现不一致 | P2 |
| M9 | tooltip、popover 收回的 100ms 写死，收回用 `ease`，不是令牌 | P2 |

## 3. 决定

- **D82 按下立即反馈**：所有能点的东西按下时不过渡（和悬停一样），松开照旧 140ms 淡回。小程序的按下（`.is-active` / `.is-hover`）同样。
- **D83 每个能点的东西按下时都有看得见的变化**：
  - 没有自己按下样式的透明底控件，按下统一深一档：`--wash-strong`（浮层里 `--wash-strong-raised`）。
  - 链接按下时下划线变成字色（和悬停一样）。
  - 开关、复选、单选、分段、tab 按下后状态立刻变，不另加。
- **D84 减少动效下进行中的按钮**：转圈换成和 `.xxd-spinner` 一样的慢淡入淡出（不转、不定住）。
- **D85 进行中延迟 150ms 才露出来**：`aria-busy` 立刻生效（防连点），字变透明、出现转圈晚 150ms。
- **D86 完成反馈对所有按钮都有**：有图标的照旧换成勾；没图标的，字透明、中间出现一个勾，1 秒后恢复（宽度不跳）。
- **D87 toast 的时长按内容算**：
  - 只是告知：max(2.6 秒, 1.2 秒 + 每字 0.1 秒)，最多 8 秒；
  - 出错：至少 6 秒；带操作：10 秒（不变）；
  - 页面在后台时暂停，回来以后重新计时。
- **D88 复制的备用路径把焦点还回去**。
- **D89 新令牌 `--motion-out`（100ms，浮层收回）**：收回的缓动也用令牌。
  原则 §8 改写成「减少动效：一次性全部静止；只有表示正在进行的转圈、加载条换成很慢的淡入淡出，不定住」。
- **D90 门禁**：
  - audit 加 `--only=motion`：
    - 强制 :active，按下的同一刻就要有看得见的变化；
    - 减少动效下还在跑的动画只能是慢淡入淡出；
    - 进行中的按钮在减少动效下不能是定住的弧。
  - 刻度测试：transition 只许 opacity / transform / 颜色类属性，时长、缓动写令牌（循环动画除外）。

## 5. 没改的

- **转圈、加载条、骨架屏的循环时长**（0.7s、1.1s、1.4s）不做成令牌：它们是循环动画的节奏，不是状态过渡；减少动效下都换成同一个慢淡入淡出。
- **收回的缓动用 `ease`**：100ms 太短，换哪种曲线肉眼都看不出来，不另起令牌。
- **小程序 toast 悬停暂停**：手机上没有悬停；按住时暂停要改 Taro 的触摸事件，这一轮不做（网页版有）。
