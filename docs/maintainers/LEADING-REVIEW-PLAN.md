# 行高（字号和行高成对）

> 2026-11-11。接着 TOUCH-REVIEW-PLAN 的 D161 编号（D162 起），AI 定，维护者可以改。做完在第 4 节打勾写日期。
> 起因：有人说 UI Kit 的行高「没有章法」，一些地方的字读着挤。

---

## 0. 结论

- **规则本来就有**（DESIGN-PRINCIPLES §6：字号和行高成对，落在 4px 网格上），**是实现走样了，门禁又看不见**：
  1. 会折行的说明用了只给一行的 12 / 16（行距 1.33，中文两行几乎贴在一起）；
  2. `--leading-*` 是 px，只改字号的规则把行高原样继承下来：正文里的表格 13 / 28（`/tools` 一格 8 行）、`data-size="lg"` 的文字 16 / 20；
  3. 行高 1 的字折了行：英文顶栏的搜索框占位字在 1280 宽折成两行，两行字贴在一起；
  4. 门禁只问「行高在不在 {16, 20, 24, 28, 32, 36} 里，或者等于字号」，不看字号、不看折了几行，`normal` 直接放过，Kumo 不查，顶栏和 React 演示也没进检查范围。
- **不改令牌**：不换成按用途命名的 `--type-*`，`--text-*` / `--leading-*` 照旧。改的是「怎么配」和「怎么查」。

## 1. 怎么测的

- 展示站构建以后，331 页 × 1280 / 390 宽，量每个有字的元素算出来的字号、行高和实际折成几行；再把长中文放进说明、tooltip、dock 状态、登录条款、图注、`data-size="lg"`、正文表格，看算出来的一对。
- 门禁改完先跑一遍，记下失败的清单，再改到全绿（第 4 节有前后数字）。

## 3. 决定

- **D162 一张表，按用途成对**：用途 → 字号 / 行高 / 能不能折行。只一行：角标 11 / 16、标签 12 / 16、单行控件「行高 = 字号」；会折行：说明 12 / 20、界面 13 / 20 和 14 / 20、说明页段落 14 / 24、标题 16 / 24、阅读 16 / 28、节标题 20 / 28、页标题 24 / 32、展示 28 / 36。
  写在 DESIGN-PRINCIPLES §6；门禁（`polish.js` 的 `PAIRS`）就是这张表，查的规则都从它推出来，不另写条件。
- **D163 会折行的说明一律 12 / 20**：L1 全部改成 `--leading-sm`。只有一行的说明也跟着高 4px，不分「单行说明」「多行说明」两个变体（COMPONENT-JURY-PLAN 里记着的那条）。
- **D164 改字号必须同时写配对的行高**：同一条规则里写，按用途从表里挑：
  - 正文表格 13 / 20；`.xxd-text` 的 `data-size` xs 12 / 20、sm 13 / 20、base 14 / 20、lg 16 / 24；
  - 统计的单位 12 / 20；面包屑 12 / 20（单行，正文外本来就是 20，不变高）；
  - 量表的数 20 / 28、小号 16 / 24、大号 24 / 32（表里的一对，数字放不下时会断开，不用只能一行的「行高 = 字号」）；
  - 标志的名字 14 / 20、大号 16 / 24；展示站令牌名 11 / 16。
- **D165 「行高 = 字号」只给一行的字**：顶栏搜索框的占位字是标签，一行、放不下在末尾省略（TRUNCATION D91、D92），字自己 12 / 16，按钮还是行高 1。
- **D166 Kumo 在绑定层改**（`kumo-binding.css`，不动组件源码）：`leading-snug` / `leading-normal` 只用在 12–14px 的说明、横幅、空状态上，配 20；表头、菜单项 12 / 16。
- **D167 门禁**：audit「细节」的第 5 项换掉：
  - 算出来的（字号, 行高）不在表里、也不是「行高 = 字号」→「行高和字号不成对」；`normal` 也算；
  - 只一行的那几对，元素自己的字（Range 量每一行的上沿，差不到 0.6 个字号算同一行）折成 2 行以上 →「单行的行高折了行」；
  - 除了组件（`xxd-`）、展示站（`site-`），也查 Kumo（`[data-kumo-component]` 里，或者带 `kumo-` 的类名，横幅和字段没有那个属性）；
  - 每页除了正文，顶栏也查；组件页把「React」标签页里的演示打开再查一遍（这一遍只看行高）。
- **D168 侧栏图标条的标签 12 / 20**（维护者定，2026-11-11）：48 宽放不下一个词时照旧断开（J16），会折行就配会折行的一对；每项高 4px。门禁不再给它开例外。

## 5. 没改的

- **React 演示里行高以外的毛病**（这次第一次把 React 演示放进「细节」才看到）：卡片层（LayerCard）的操作行压住标题 8px；密钥输入框的标签和框左边差 1px；时间线两项左边差一点。不在这一轮，「细节」的 React 那一遍只报行高。
- **没有静态检查**：「改字号的规则同时写行高」只靠渲染以后的门禁兜住，没写成 CSS 的 lint——很多规则改字号以后继承下来的行高本来就对（比如 12px 的标签在 20 的行里），静态规则会误报。
