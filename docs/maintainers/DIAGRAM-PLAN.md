## 0. 结论

**有必要加，但只做 6 种，不照搬 45 种。**

1. **缺的是「说明关系」的图，不是「画数」的图。** 数据图前几轮已经补齐了：§14 的选图表里，条形榜、构成条、热力格、前后对比、雷达、四象限、量表都有，
   还有 ECharts 和 Kumo 的折线、桑基、地图。现在缺的是另一类：几步做完一件事、先后发生了什么、一个分成几个、走到这里分两条路、做完又回到开头。
   插件的新手引导、会员站的「怎么用」、更新记录、心理测试站的结果说明、多步表单的步骤条，现在都是各写各的，或者干脆只写一段字。
2. **45 种里大部分我们用不上，或者已经有了。** 按用途分（第 2 节逐个列）：
   - 约 17 种是**数据图**：条形、瀑布、热力、折线、散点、雷达、桑基、树图、甘特……我们已经有，或者 §14 有意不做。
   - 约 15 种是**工程文档图**：架构、部署、数据湖分层、权限矩阵、UML、库表、依赖图、沃德利地图、等距爆炸图……
     这些是给工程师画一次、放进文档里的图，不是产品界面里反复用的组件。
   - 剩下的**概念图**里，6 种在小小东的产品里真会反复出现：步骤、时间线、流程（带分支）、树、循环、分层。
3. **做成组件，线用 CSS 边框画，不用 SVG 连线。** 节点和字都是 HTML，连线是框的边框和伪元素。这样做的好处：
   - 读屏念的是一张有序列表，不用另写一句话；
   - 高对比模式下系统自动换色；
   - 打印、从右往左、窄屏重排都跟着 CSS 走；
   - 小程序能照搬；
   - 不需要 JS。

   代价是只能画固定的几种结构：一条线、分叉再合拢、树、回到开头。画不了任意连线的网状图。这正好守住 §14「不做网络图」。
4. **一次性的工程图交给 AI 技能，不做组件**（第二阶段，第 5 节）。借 diagram-design 的方法，换成我们的令牌和字体，给文章、README、文档用。

## 2. diagram-design 的 45 种：我们怎么处理

| 它的图 | 我们 | 理由 |
| --- | --- | --- |
| Process（多步）、Flowchart（带判断） | **做**：步骤 `Steps`、流程 `Flowchart` | 产品里最常见 |
| Timeline | **做**：时间线 `Timeline` | 更新记录、状态历史 |
| Tree、Org chart、Nested | **做**：树 `Tree`（Nested 用卡片套卡片就够） | 菜单、分类、组织 |
| Loop | **做**：循环 `Cycle`，画成一排加一根回头线，不画成一圈 | §14 不做放射图 |
| Layer stack、Pyramid | **做**：分层 `Layers`；金字塔不做 | 金字塔的宽窄不是数据；转化漏斗已经是条形榜的一种 |
| Swimlane、User journey、Service blueprint、Story map | 先不做 | 要好几列、宽屏才放得下；真用到时用 `Steps` 分组或表格 |
| Venn | 不做 | 圆的大小和重叠面积读不准；两三个集合的关系用表格或一句话 |
| Quadrant、Radar | 已有 | CHART-TYPES-PLAN 第 9 节 |
| Bar、Waterfall、Heatmap、Line（含 slopegraph、bump）、Scatter、Sankey、Treemap、Polar、Gantt | 已有或不做 | 条形榜、瀑布、热力格、前后对比、ECharts、Kumo 桑基；树图、极坐标图 §14 不做；甘特图要的时候用 ECharts |
| Kanban | 不是图 | 这是界面（列表加拖动），要的时候单独做 |
| Architecture、Architecture delta、IT state、High-level、Deployment、Data flow、DP integration、DP security matrix、Medallion、Dependency、UML class、ER、DB schema、Wardley、Fishbone | 交给第二阶段的技能 | 工程文档图，节点和连线都是任意的；权限矩阵本来就该是表格 |
| Exploded、Axonometric plan | 不做 | 等距 3D，§1 不要 3D |
| 手绘风、终端窗口风、动画 | 不做 | §1 气质、§8 不做进场动画 |

**借它的规则**（写进组件的「规则」和 audit）：

- 能删就删：每个节点是一个独立的意思，总是一起出现的两个节点合成一个。
- 重点最多 1–2 个。
- 节点超过 9 个就拆成总览加细节。
- 连线只走直角。
- 线不穿过和它无关的框。
- 线上的字不压线。
- 同一条边上的几根线各有各的接点。
- 一张表格能说清的事，不画图。

**不借**：

- 它的衬线标题和网络字体：我们只用系统无衬线字，不加载网络字体（§6）。
- 窄屏横向滚动（它的 `min-width` 加 `overflow-x: auto`）：我们在窄屏重排，见 D142。

### 4.1 audit `--only=diagram` 查什么

- **线接得上**：每根连线的两头离对应节点的边 ≤ 1px；分叉的横线正好盖住第一条和最后一条分支的中线。
- **线不穿框**：连线和不是它两头的节点不相交。
- **字不压线**：线上的字的框和线不相交，离线 ≥ 4px。
- **窄屏**：320 宽下整页没有横向滚动，横排的组件已经变成竖排。
- **高对比（亮 / 暗）**：线和框都在，线和 Canvas 的对比 ≥ 3:1。
- **暗黑、局部主题、打印、从右往左**：线的方向镜像，打印是亮色、不被切。
- **读屏**：是 `ol` / `ul`；当前步有 `aria-current`；线 `aria-hidden`；`Cycle` 有「回到第 1 步」。
- **上限**：塞 12 个节点时有一次 `console.warn`，页面不乱。
- 先用一个故意画错的页面跑一遍，确认这些检查真能抓出问题（和前几轮一样）。

## 8. 第一批做的时候定下的细节（2026-10-30）

维护者说「按你的建议，开始做第一批」，第 7 节三个问题按建议定：`Steps` 兼做多步表单的步骤条；技能以后再说；先用真内容做（见下面最后一条）。

  四象限上一轮也是这么改的。横排的线从标记右边 8px 画到这一步的末尾前 8px（也就是下一步标记的前 8px）；竖排的线在标记正下方，上下各空 4px。
  高对比模式下边框跟着换成系统色，背景画的东西（做完的实心标记、时间线的点）在 `forced-colors.css` 里用系统色重画，当前这步是 Highlight 框。

- **小程序里本来就有一个 `Steps`**（小程序第一版做的：横排是每步上面一根线、没有编号，竖排才有圆标记）。现在改成网页版的样子，三种实现一样；
  小程序专有的 `src/styles/Steps.css` 删掉了。小程序没有 `aria-current`，当前和做完写进每一项的读屏名字（「选套餐（当前）」）。
