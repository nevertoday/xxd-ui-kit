# 字体和字号层级（对抗测试）

> 2026-10-22。接着间距、圆角和线两轮，专门挑字：层级分不分得开、字号在不在阶梯上、字重有没有越界、换一台电脑的字体会不会坏、中英文混排。
> 决定接着 SHAPE-LINE-PLAN 编号（D66 起），AI 先定，维护者可以改。做完在第 4 节打勾写日期。

---

## 0. 结论

**字体选得没问题，坏在层级和几处「浏览器自己加的」样式。**

- 经得起打的：
  - 中英文在按钮、输入框、徽标里的竖直居中都在 1px 以内；
  - 把西文换成很宽的 Verdana，148 页没有一处字被截断、折行或伸出去；
  - 中英文之间的空格全站一致，没有弯引号，没有字距和大小写变换；
  - 全站只有两套字体（正文、等宽）。
- 坏的：
  1. **展示站的层级是「头重、中间挤」**：页面标题 28，节标题一下掉到 16，小节 14，正文 13。
     - 节标题和页面导语一样大（都是 16）；
     - 小节标题比正文只大 1px；
     - 展示站自己没用组件库的标题档（组件的 heading2 是 20、heading3 是 16）。
  2. **等宽字「小 1px」在大字旁边出了阶梯**：136 个组件页标题里的英文名是 27px，导语和正文里的代码是 15px。
  3. **浏览器默认的粗体是 700**：`<b>`、`<strong>`、`<th>` 没人管，表格、正文、规则列表里出现了 700（字重只许 400 / 500 / 600）。
  4. **中文被斜体**：代码块的注释是斜体，苹方没有斜体，浏览器把字硬拉斜。
  5. **11px 的中文**：「草稿」徽标、tooltip、菜单的分组名、侧栏的分组名、目录标题、选项提示、登录页的条款……
     - Windows 1 倍屏上微软雅黑 11px 发糊；
     - 一些中文环境的浏览器会把最小字号设成 12px，这时这些地方都会变大。

## 1. 怎么测的

- **逐字**：展示站 296 页（中英），每个直接带字的元素读计算样式：字号、行高、字重、第一个字体、斜体、字距、大小写、数字是不是等宽。
  按组件归类，挑出不在阶梯上的字号、400 / 500 / 600 以外的字重、斜体、`line-height: normal`。
- **层级**：每页 `main` 里的 h1–h6 和正文段落的字号、字重，算相邻两级的比例。
- **竖直居中**：按钮（三种高）、徽标、chip、输入框，各放一段中文、一段英文、一段带下行字母的英文、一段数字，4 倍截图量墨迹的上下空白。
- **换字体**：把 `--font-body` 的西文换成 Verdana（比 Avenir Next、Segoe UI 都宽），组件、模式、模板、首页在 1280 / 390 宽各跑一遍「细节」检查。
- **内容**：注册表的中文说明里，中英文之间有没有空格、有没有弯引号。

## 2. 发现

严重度：**P0** 一眼看得出层级乱；**P1** 违反了写下来的规则；**P2** 打磨。

### A. 层级

- **A1 展示站的层级**（P0）：

  | 级 | 现在 | 组件库的档 |
  |---|---|---|
  | 页面标题 h1 | 28 / 36 · 600 | display 28 / 36 · 600 |
  | 节标题 h2（演示、规格、属性……） | **16 / 24 · 600** | heading2 20 / 28 · 600 |
  | 小节标题 h3 | **14 / 20 · 500** | heading3 16 / 24 · 500 |
  | 导语 | 16 / 28 · 400（灰） | — |
  | 段落、规则列表 | **13 / 24、13 / 20** | 正文 |

  相邻两级的比例是 1.75、1.14、1.08：上面一下掉太多，下面挤成一片。
- **A2 块里的标题有两种字重**（P1）：
  - 卡片、底部面板、右侧面板、popover、横幅、顶栏的标题都是 13 · 500，只有图表卡的标题是 13 · 600。
  - 空状态的标题是 14 · 500，不在任何一档上。
  - 统计数字的后备值还写着已经不用的 `22px`。

### B. 字号、字重、字形

- **B1 等宽字出了阶梯**（P1）：`calc(1em - 1px)` 在 12、13、14 旁边正好落在 11、12、13；在 16 旁边是 15，在 28 旁边是 27。
- **B2 字重 700**（P1）：98 处，来自 `<b>`、`<strong>`、`<th>` 的浏览器默认值。
  在表格（颜色页的对比度数字）、正文、规则列表、开始页里都有。
- **B3 中文斜体**（P1）：代码块注释 `font-style: italic`，里面有中文时被硬拉斜。
- **B4 11px 的中文**（P1）：
  - 组件里：xs 按钮、xs 下拉、小面包屑、徽标、tooltip、菜单的分组名、选项的提示、
    侧栏的分组名、目录标题、登录页的「或者」和条款、套餐的小字、聊天气泡；
  - 展示站：侧栏分组名、目录标题、状态矩阵的标签、组件墙的名字、「外观」浮层的小标题。
  - 原则只写了「tooltip 11px、移动端侧栏标签 11px」，没说中文能不能小于 12。
- **B5 行高 normal**（P2）：展示站侧栏里的英文名、搜索框的占位字、组件墙的名字、图标页的数量。
- **B6 量表中间的大数字不是等宽数字**（P2）：它会从 0 跳到目标值，数字宽度不一样，整块左右晃。

### C. 门禁

- 现在只查 CSS 里写的值（字号写令牌、行高成对）。
- 浏览器自己加的样式（`<b>` 的 700、`<em>` 的斜体）、算出来的字号（27、15）、11px 的中文，都没人看。

## 3. 决定

- **D66 展示站用组件库的标题档**：
  - 节标题 = heading2（20 / 28 · 600）；
  - 小节标题 = heading3（16 / 24 · 500）；
  - 段落和规则列表 = 14 / 24；导语 16 / 28 灰色不变。
  - 相邻两级的比例变成 1.4、1.25、1.14（再加字重），每一级都分得开。
  - 14 / 24 加进「字号和行高成对」的表：它是说明页的段落（中文要 1.7 的行距才好读；16 / 28 是阅读正文）。
- **D67 字重 600 只给「整屏的标题」和大数字**：
  - 600：页面标题、节标题、对话框标题、统计和量表的数字；
  - 500：块里的标题（卡片、面板、横幅、图表卡、popover、空状态）；
  - 图表卡标题改成 500，空状态标题改成 heading3（16 / 24 · 500），统计数字去掉 `22px` 后备值。
- **D68 `<b>`、`<strong>`、`<th>` 一律 600**：组件库和展示站的基础样式里统一写，不靠浏览器。
- **D69 等宽字比周围小「一档」**（在阶梯上），不是小 1px：
  - 写成 `max(var(--text-xs), calc(1em - clamp(1px, 1em - 14px, 4px)))`；
  - 结果：13 → 12、14 → 13、16 → 14、20 → 16、24 → 20、28 → 24；在 12 旁边仍是 12。
    回归时图标页的「pnpm xxd icon 删除」在 12 的说明里变成了 11px 的中文，所以加了下限（D71 优先）。
- **D70 不用斜体**：中文没有真斜体。代码注释只靠灰色；正文的 `<em>` 在中文里不斜（英文照旧）。
- **D71 中文不小于 12px**：
  - 11px 只给不会出现中文的东西：键帽和快捷键、等宽的名字（类名、文件名、属性类型）、图上的刻度数字、小程序的标签栏（MINI D29）。
  - 上面 B4 列的都改成 12px。
- **D72 行高不写 normal**；量表的数字用等宽数字。
- **D73 门禁**：audit「细节」加三项：
  - 字号不在阶梯上（算出来的）；
  - 字重不是 400 / 500 / 600；
  - 中文斜体、中文小于 12px。
  - 「行高不在网格」也扫展示站自己的字。
  - 刻度测试：`font-style: italic` 不许出现；`--text-2xs` 只许名单里的选择器用。

## 5. 没改的

- **字体本身**：Avenir Next + 苹方（macOS）、Segoe UI + 雅黑（Windows）不换。
  - 竖直居中实测都在 1px 以内；
  - 换成更宽的 Verdana 也没有一处坏；
  - 只用系统字体是硬规则。
- **11px 的英文和数字**（键帽、类名、刻度）：它们不会碰到中文字形的问题；等宽字在 12 的表格里小一档就是 11。
- **小程序的底部标签栏**：11px 照旧（MINI D29：手机上只有它和角标数字小于 12）。
- **`--text-md`（15px）变量还在**：外面的老代码可能在用；门禁不许新代码用。
- **组件墙的名字、展示站侧栏里的英文名**：等宽 11px，只有英文。
- **换宽字体时侧栏图标下的「Settings」差一点撑满**（12px 下 46px，格子 48px）：没有截断，先不改；以后加更长的英文标签要换成图标 + tooltip。
